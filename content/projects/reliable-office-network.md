## Why It Matters

Many practical IT problems start with uncertainty. A router gets changed, a switch port is repurposed, a printer moves,
or a Wi-Fi password changes. None of those events are complicated alone, but they become painful when nobody can see the
current shape of the system.

This project treats documentation as infrastructure. The goal is not to create a large diagram once. The goal is to keep a
small set of notes alive:

- device names and roles
- important IP ranges
- management access locations
- recovery steps
- recent changes

## What I Would Track

I would keep the core network notes inside the repository alongside the public case study. Private values stay out of the
public version, but the structure remains visible enough to show how the work is organized.

## Portfolio Value

This is a good example of practical IT engineering because it shows judgment. Reliable systems depend on the habits around
the tools, not only the tools themselves.
